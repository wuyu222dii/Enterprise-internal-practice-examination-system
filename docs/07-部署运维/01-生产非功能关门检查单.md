## 1. 压测机 PERF-01~03

必须在独立压测机执行 [`scripts/load-test/run-full-perf.sh`](../../scripts/load-test/run-full-perf.sh)（默认 500 VU × 30min）。禁止把本机抽样行抄进 [验收追踪](../06-测试验收/验收追踪.md) 的 PERF 空表。

```bash
docker exec -i exam_system-postgres-1 psql -U exam -d exam_system < scripts/load-test/seed-capacity.sql
EXAM_ID=$(scripts/load-test/setup-capacity-exam.sh | tail -1)
EXAM_ID=$EXAM_ID scripts/load-test/run-full-perf.sh
```

压测机实测后，只填写验收追踪中「待压测机」空表（环境 / P50 / P95 / P99 / 失败 / 日期）。未跑满 500 人不得标通过。

- [ ] PERF-01 500 人 30min 保存（P95 ≤ 1s）
- [ ] PERF-02 60 秒集中开卷/交卷（P95 ≤ 3s）
- [ ] PERF-03 同秒到期自动交卷（500 唯一提交）

## 2. 生产窗口 DR

勾选 [`scripts/ops/README.md`](../../scripts/ops/README.md) 中的生产窗口检查单。本机开发库不算 DR 关门。

切换窗口前：

- [ ] `scripts/ops/backup.sh` 成功，对象含 PostgreSQL dump，排除 `credentials/`
- [ ] 对空库/演练库跑过 `restore.sh`
- [ ] 生产 `EXAM_STORAGE_BACKEND=minio`；本地保持 `local`
- [ ] Prometheus 抓取 `/api/v1/actuator/prometheus`（需认证，见 [00-本地与生产部署](00-本地与生产部署.md) §5），health 告警已接值班
- [ ] PERF 空表仍空则不得把本机抽样当作发布门禁通过

切换窗口中：

- [ ] 执行备份 → 切换 → `GET /api/v1/actuator/health` = UP
- [ ] 管理员登录 + 抽查一场监控页 lifecycle / run / 参与维

回滚：窗口前 dump + `restore.sh`，配置回到上一版本。

## 3. 生产通道（MinIO / 短信 / 微信）

密钥只放环境变量或密钥管理。仓库 `.env.example` 仅占位。

| 通道 | 本地默认 | 生产 |
| --- | --- | --- |
| 对象存储 | `exam.storage.backend=local` | `EXAM_STORAGE_BACKEND=minio` + `EXAM_MINIO_*` |
| 短信 | `exam.sms.provider=mock`（验证码固定 123456） | `EXAM_SMS_PROVIDER=aliyun` 或 `tencent`，配齐密钥；未配密钥须拒绝发送 |
| 微信 | `exam.wechat.mock-openid=true` | `EXAM_WECHAT_APP_ID` / `EXAM_WECHAT_APP_SECRET` 调 `jscode2session`，关闭 mock |

- [ ] MinIO bucket `exam-files` 已创建，应用可读写导出与导题文件
- [ ] 真短信发送与校验在非 mock 环境走通（绑定 / 找回）
- [ ] 小程序 `config.js` 的 `apiBase` 为 HTTPS 域名，公众平台已配 request 合法域名
- [ ] `code2Session` 使用真实 AppId/Secret，不再依赖 mock openId
